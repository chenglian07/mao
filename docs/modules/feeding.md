# 远程投喂与投喂追溯

> 核心能力二 | 等级：P0 | 状态：**软件已实现，待验证**

---

## 功能定位

用户通过平台对指定猫咪执行投喂操作，系统记录完整的投喂链路（谁、何时、喂了哪只猫），所有记录可追溯、可查询、可导出。

**重要说明**：当前投喂操作为软件层面记录（数据库中的计数和日志），尚未对接真实投喂机械装置。用户在平台上点击"投喂"后，系统记录该行为但不触发物理投喂动作。

## 投喂流程

### 登录用户

1. 在首页或猫咪档案页点击"投喂"按钮。
2. 系统自动使用登录用户名，执行投喂。
3. 猫咪 `feed_count` +1，用户积分 +1。
4. 投喂日志追加到 `data.json`。
5. 自学习引擎自动更新猫咪画像和用户偏好。

### 游客

1. 点击"投喂"按钮，填写昵称。
2. 系统通过 `guest_id` 检查投喂次数。
3. 首次投喂成功，第 2 次被拒绝并提示登录。

## 投喂记录字段

| 字段 | 说明 | 示例 |
|------|------|------|
| id | 记录 ID | 1 |
| cat_id | 目标猫咪 ID | 1 |
| user_name | 投喂者昵称 | 小明 |
| user_id | 用户 ID（登录用户） | abc123 |
| time | 投喂时间（ISO 8601） | 2026-10-19T14:32:05 |
| type | 投喂类型 | user / guest |

## 数据存储

- 投喂日志存储于 `data.json` 的 `feed_logs` 字段
- 上限 500 条（通过环境变量 `PROJECTCAT_MAX_FEED_LOGS` 调整）
- 全量数据可通过 `/api/export` 一键导出

## 自学习子能力

投喂操作完成后，系统自动触发自学习引擎（`self_learning.py`）：

| 能力 | 说明 | 技术实现 |
|------|------|---------|
| 投喂规律学习 | 统计每只猫的日均投喂次数、高峰时段 | `Counter(feed_hours)` 统计分析 |
| 异常投喂提醒 | 单日投喂超历史均值 2 倍时生成预警 | 规则引擎判断 |
| 阈值自校准 | 根据累积数据自动调整告警阈值 | 统计规则动态调整 |
| 用户偏好学习 | 记录用户关注的猫咪和投喂时段 | 用户画像数据结构 |

查询接口：
- 猫咪画像：`GET /api/learning/cat-profile/<id>`
- 用户画像：`GET /api/learning/user-profile/<user_id>`
- 异常预警：`GET /api/learning/anomalies`

详见 [自学习模块说明](../self-learning.md)。

## 数据来源

| 数据项 | 来源 | 说明 |
|--------|------|------|
| 投喂操作 | 用户手动触发 | 软件记录，非物理投喂 |
| 投喂日志 | 后端自动生成 | 每次投喂追加一条记录 |
| 猫咪画像 | 自学习引擎分析 | 基于投喂日志的统计结果 |
| 异常预警 | 规则引擎检测 | 基于统计规则，非 ML 模型 |

## 验收标准

1. 游客模式投喂 1 次后，系统拒绝第 2 次并提示登录。
2. 登录用户可连续投喂，每次操作后猫咪 `feed_count` 准确 +1。
3. 投喂记录可通过 `/api/feed-logs` 查询，字段完整且时间戳准确。
4. 投喂后 `/api/learning/cat-profile/<id>` 返回的 `peak_hours` 与 `avg_daily_feeds` 与数据一致。
5. 短时间内大量投喂（超均值 2 倍）后，`/api/learning/anomalies` 出现异常记录。
